# 主模型只有一个，fallback 只留阿里云直供，额度按真实单价封顶

## 2026-09-13 · Grok 主模型，千问备用

用户指定 Next 后端默认使用自有 Grok 网关的 `grok-4.6`，失败时只切到当前 DashScope `qwen3.8-flash`。此裁决覆盖下文原有主模型和候选备用链；ASR 与联网搜索仍使用各自现有千问接口。

连接说明：[Grok 网关接入 Supabase Edge Function 与 Vercel AI SDK](https://app.notion.com/p/3daf5b5cf6c481989604f8188ffd3054)。该网关现已支持 `/v1/chat/completions`，以实际调用验证，沿用项目 `ai@4.3.16` 与 compatible provider，未升级整个 SDK。`GROK_BASE_URL`、`GROK_API_KEY` 只由服务端 secrets 提供，`GROK_MODEL` 默认 `grok-4.6`；`DASHSCOPE_MODEL` 默认 `qwen3.8-flash`。旧 Vercel Gateway 与 Kimi/DeepSeek 候选不再参与此链。

主对话、读图、估餐、会话记忆都使用这条链。单个供应商 HTTP 请求上限30秒，为备用留出时间；整轮截止时间、用户取消、权限、额度与持久化错误仍直接终止。只重试当前尚未执行工具的模型步骤，保留已完成步骤，不重复手机操作。图片转录的长度在类型验证后做上下文裁剪；两家读图都失败时返回明确工具失败，让模型说明限制或尝试原图估餐。

各次成功调用按实际模型 ID 与 token 用量记录。网关使用周额度；现有数据库金额门禁仍对未配置专属价格的模型应用 `*` 估算价格，此估算不代表 Grok 的真实现金账单。本次不修改既有用户额度或数据库价格表。

验证与上线：302 个后端测试及 lint 通过；真实网关完成流式工具调用往返、891 字符/36 个数字的合成订单图识别、估餐草稿。生产项目 `gkgzwcxivnffsecshvfs` 已部署 `turn v87` 和 `memory-settle v6`，均保留 JWT 校验。演示账号线上聊天及订单图请求成功，数据库各次调用均为 `grok-4.6`；同 operation 重放未增加模型调用，未认证请求返回401。故障注入测试覆盖千问切换与不重放已开始的工具步骤；未人为中断生产 Grok 服务。

2026-09-05 用户确认：文本、视觉与 chat 统一走同一个模型；保留 fallback 但不许降级到小模型；按真实价格设每日额度，目标是让用户免费用三年。

`qwen3.8-flash` 承担文本、视觉与 chat 三条路。官方模型页现在列的输入模态是 Image / Text / Video，调用格式就是 OpenAI 兼容的 `image_url` content part，走的还是同一个端点，所以 `visionModel()` 与 `VISION_MODEL_VERSION` 可以撤掉，`meal` 的照片路径与 `turn` 的 `image.inspect` 都改走 `model()`。撤掉之前必须先用真实照片打一次验证：`docs/STATUS.md` 记着的实测结论是该模型"没有图片输入"，与现行文档冲突，可能是当时尚未具备、也可能当时试的是 Gateway 通道。同一次验证顺手记下 `usage`，用来校准下面所有 token 估算。不存在 `qwen3.8-vl-*`；自 Qwen3.5 起主线系列原生多模态，独立 VL 产品线不再迭代，`qwen3-vl-flash` 在新加坡地域不支持 Function Calling，这一点主线模型没有。

ASR 保持独立模型。两代千问文本模型都不接受音频输入，视觉理解文档还专门写明不支持理解视频里的音轨。「语音输入的结果由主模型处理」这条今天已经成立——ASR 只吐文本，文本进 `/turn` 走主模型，没有第二个模型参与理解。实时通道保留：它买到的不是字幕（`ASRStreamingSession` 只处理 `done` 与 `error`，任何中间结果走 `default: break` 丢掉），而是"说话时就在上传"带来的松手后延迟；实时版 ¥0.00033/秒 对非实时版 ¥0.00022/秒，顶格用量一年只差约 ¥3.2，不值得用延迟去换。WAV 上传仍是 socket 或供应商失败时的兜底。

fallback 链只收阿里云百炼**直供**的模型，即模型 id 不带厂商前缀的那批。候选是 `kimi-k3`（可读图，¥20/¥100）与 `deepseek-v4-flash`（纯文本，¥1/¥2）。带前缀的原厂直供（`ZHIPU/`、`kimi/`、`MiniMax/`、`vanchin/`）不进链：虽然挂在百炼上、同一个 key 同一个 baseURL，但推理请求实际落到厂商侧，各自条款里保留的「使用输入输出改进服务」或「用匿名数据训练算法」重新生效，而百炼按量付费 API 明确承诺不将数据用于训练。`ZHIPU/GLM-5.3-Flash` 因此出链，尽管它便宜（¥0.8/¥2.8）且四项能力齐全。`qwen3.8-flash-next` 也出链：它不在百炼上（百炼文档 404），Vercel 上由第三方托管且能力元数据缺失，过不了准入门槛；等它进百炼再议。fallback 只在主模型不可用时触发，选型标准是合规干净与能力齐全，不是便宜。

准入门槛是工具调用、结构化输出、流式 `reasoning_content` 三项齐全。三家的思维链字段名统一是 `reasoning_content`，这一点省了一层抽象。但严格 JSON Schema 约束（`response_format: json_schema`）在百炼上只有 Qwen 系列支持，第三方全部只到 `json_object`，所以 `streamText` 加工具那条主路径（依赖 function calling 的参数 schema）fallback 时是安全的，`generateObject` 那两条路（估餐与 `image.inspect`）会退化成"提示词要求 JSON 加自己校验重试"。DeepSeek 另有一条硬约束：带 `tools` 的请求后续每一轮都必须完整回传 `reasoning_content`，不回传直接 400；千问只是降低准确性。`docs/prd/F4-server-ai.md` 里「主模型 3 秒无 token 就切小模型」那条作废——它从未实现，且与「不许降级到不可用状态」直接冲突。

成本按真实单价重算的结论是 PRD 的目标破了。北京地域 `qwen3.8-flash` 输入 ¥0.8/百万、输出 ¥2.7/百万、缓存命中输入 ¥0.1/百万（12.5%，是通用 20% 规则的例外）。PRD 按每轮输入 5.5k、输出 600 估出 ¥0.006/轮，那个数没拍错，它对应"一轮一次调用"；多步工具调用每步重发全上下文，四步累计输入约 84k，是该假设的 15 倍，单轮约 ¥0.083，重度用户 30 轮/天折算约 $10.6/月，是 $0.9 目标的十二倍。压到三次调用并吃到轮内前缀缓存后单轮约 ¥0.0089。顶格 10 轮/天、每轮 8 秒语音、两成轮次带照片，一年约 ¥43.6（文本 ¥32.5、语音 ¥9.6、照片 ¥1.5），三年约 ¥131；按真实日均 2.5 轮算一年约 ¥11、三年约 ¥33。免费用三年成立的前提是把一轮压到两三次调用。

隐式缓存自动开启且无法关闭，最小可缓存前缀 1024 token，不需要写任何代码——只需要系统提示词与工具定义逐字节稳定，这正是删掉关键词预路由的第二个理由（见 ADR 0006）。省下的 45% 来自同一轮内三次调用之间相隔几秒的复用，不依赖跨轮命中。显式缓存不用：`qwen3.8-flash` 的显式创建价是标准输入价的 156.25%，TTL 五分钟，移动端偶发触发的场景回不了本。图片按 `h × w / (32 × 32) + 2` 折 token，divisor 对 qwen3.8 系列确认是 32×32；一张 1024×1024 的照片是 1026 token 约 ¥0.00082，压到 512×512 只省 ¥0.0006，不值得拿食物识别准确率去换，且官方实测调小 `max_pixels` 对端到端延迟没有影响。

额度是每天 10 轮，当天未用可累积，上限 20 轮。按周（70 轮）会让用户第一天烧完、之后六天全锁，比每天 10 轮糟且难解释；纯日限则照顾不到刚戴上手环那天想连着问的情形，累积到 20 意味着最坏情况的年成本翻倍而真实用户几乎不可能天天顶格。超额是拒绝，不是降级：不跑模型，面板保留上一帧（满足 F4「面板永远不许空」），补上 PRD 已写但代码里不存在的 SLOW DOWN 说明帧。fallback 链只为"模型挂了"，额度只为"钱花完了"，两套机制不互相调用。金额上限与现有次数限流并存，谁先到谁先拦——单轮成本方差极大（一句「现在心率」与一个"看这张照片并对比过去 90 天"差几十倍），次数限流还兼职防刷与防并发，不能互相替代。

## 尚待确定的边界

token 用量目前完全没有采集：`streamText` 与 `generateObject` 的 `usage` 从未被读取，`ai_turns` 与 `screen_frames` 只有 `model_version` 与 `latency_ms`。上面每个成本数字都是按假设推算的估算，不是测量；先把 `usage` 落库并按天按用户聚合，才谈得上额度执行与成本看板。`meal` 与 `asr` 两个接口现在**完全没有限流**，而它们恰好是最贵的两条路径，任何按钱的额度必须先覆盖它们，否则绕开 `/turn` 就能无限刷。服务端日限 `_DAILY = 150` 已定义但未使用，客户端 `dailyCallsUsed` / `dailyCap` 是本地内存计数、不持久化不同步，且 `AIPanel` 一个都没绑定，本地日限超了只写 `lastError` 而 `lastError` 没有任何视图展示。用量对用户只以次数表述，不显示金额——金额会暴露单轮成本差异并引出不想解释的追问。

三处官方文档自相矛盾，上线前需在控制台或用一次实际调用确认，不得据文档转述下结论：免费额度的适用地域（中文站称华北2 北京、国际站称新加坡）、`qwen3.8-flash` 是否支持 Batch 批量推理（模型详情页五个地域均写不支持，价格页写 Batch 半价；Batch 对本产品本来不适用，且 Batch 调用不享受缓存折扣）、隐式缓存最小 token 数（中文文档 1024、英文文档 256，按 1024 规划）。ASR 类模型还需在百炼控制台逐一开通权限才能调用并消耗免费额度。DeepSeek 是否存在带视觉的变体，两份调研结论相反；对本决策无影响，因为百炼上能读图的 DeepSeek 只有 `vanchin/deepseek-ocr`，它不支持多轮对话与工具调用。百炼正在把 baseURL 迁往业务空间专属域名，API Key 按地域绑定（跨地域调用返回 401 而非 key 失效），DeepSeek 的 v3/v3.1/v3.2/r1 系列 2026-10-10 下架。
