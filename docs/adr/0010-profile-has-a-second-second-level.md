# 「我的」下有第二个二级页：测量记录

2026-09-05 用户确认：「我的」页在 COMPOSITION 热力图块之下新增一个 MEASUREMENTS 模块，列最近三条测量记录，模块底部的 ALL MEASUREMENTS 进入一整页记录清单。这一页是继设备页之后全产品第二个二级页，返回回「我的」不回首页。F1-navigation 里「设备是唯一的二级页」这条改写为「设备与测量记录是仅有的两个二级页」。

平衡检查从此开始落库，只落摘要行（结论词、心率、节拍数、离散度），不落逐拍 RR 序列。此前不存的理由是「不该在测量屏里顺手发明 schema」，现在 schema 是正式决定的。

## 否决的方案

- **底部 sheet 装完整清单**：F1 说 sheet 是「关掉回到同一滚动位置」的东西，78% 屏高的上限是为一屏内容定的。记录清单按月累积、会一直长，装进 sheet 是把页面伪装成 sheet。弃。
- **各回各家**：身体扫描并进成分详情页，平衡检查并进 Body Battery 或心率详情页。成分页讲方向不讲清单尚可容纳，但平衡检查没有天然的家，塞进 Body Battery 页会毁掉那页「解释今天为什么是 72」的单一主题。弃。
- **存逐拍序列以便回放曲线**：呈现或解读心律波形在美国属于受监管产品，代码里已经刻意避开。摘要行足够支撑「上周三是 drive 在主导」这种回看。弃。

## 由此立下的规则

- 页面的门槛不变：要做页面必须证明一屏放不下。测量记录过了这个门槛，闹钟、自动监测没有，它们仍是 sheet。
- 两个详情页之间仍然没有路：记录清单里的一行点开是一张 sheet（该次测量的全部字段），不跳成分详情页。
- 模块和清单混排、按时间倒序，不按类型分栏；只测过一种的账号不露出一行永远空着的另一种。

## 落地时定下的几件事（2026-09-05 实现）

平衡检查落 `balance_checks`（迁移 `20260905160000`）。为了不让屏幕上那个词日后被读成别的东西，摘要行同时存 `sd1_ms`、`sd2_ms`、`sdnn_ms` 与 `rest_share`，并带 `algo_version`（`poincare-1`）——屏幕上的 SPREAD 目前取 SD1。它**不叫 HRV 也不叫 RMSSD**：夜间 HRV 在 `night_hrv`，那是整夜的 RMSSD，和一次四十秒的白天离散度不可比。`AutonomicBalance` 算完即丢弃逐拍序列，表里也没有可以放它的列。

身体扫描的 sheet 只印**已经落表的字段**（体脂率、瘦体重、脂肪量、BMR、输入体重）。规格板上写的「14 个字段」目前做不到：`body_composition` 只有这几列，SDK 内存里的其余字段从未落库，拿它们凑数就是印一个刷新之后会消失的数。要补齐得先给这张表加列或加一个 `fields` jsonb，那是另一次改动。

清单的月头印年份（`SEPTEMBER 2026`），规格板上只有月名。记录会跨年，不印年份的清单在第二年就有歧义。

`NB_DEBUG_ROUTE=measurements` 与 `NB_DEBUG_SHEET=measurement` 是走查用的口子，和 `device` / `battery` 同类：DEBUG only，不是 envelope target，深链依然不落到这一页。

⚠️ `RootView` 里这两个钩子必须留在 `body` 之外的静态函数里。写进 `.onAppear` 的表达式链会让整个 `rootStack` 的类型推断当场超时（`error: unable to type-check this expression in reasonable time`）。
