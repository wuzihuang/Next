# 热量页也有日 / 周 / 月，月只讲典型的一天

2026-09-05 用户确认：热量页按 Paper `09H` 落地。同一页 `CALORIES`，顶上是 `SegmentedPills`（DAY / WEEK / MONTH）。这重开了 ADR 0008、ADR 0013 和 `docs/prd/09-fuel.md` 里「燃料页 V1 故意删掉日/周/月」那一句。训练页的三档见 ADR 0015。

三个英文词和睡眠 / HEART / RESPONSE 一样，窗口不是同一套。热量的时钟是用户日（本地 0 点切日，ADR 0020）。日是 1 个用户日，周是滚动 7 个用户日，月是滚动 28 个用户日（四周）。不是自然周月——周一或月初塌成一两根柱子，用户会读成数据丢了。也不是 HEART / RESPONSE 的 30 天：月在这里必须能切成整周，才能把一周说成「一天平均」。

三档说的不是同一句话。DAY 是当天的钟：顶上 09E-C 日曲线（橙阶梯 IN、青斜线 OUT、NOW、BUDGET；实线已发生，虚线按节奏推），下面一份不分餐的食物表（TIME / ITEM / KCAL / P / C / F）。没有 breakfast / lunch / dinner 分组。IN / OUT / GAP 是当天的数。WEEK 的英雄数是七天窗口内已记录值的加总（如 14,870），IN / OUT / GAP 上下三行，下面七天橙/青对柱和七天台账。MONTH 只讲 **A TYPICAL DAY**：量级是 2,xxx，不是 72,370。28 根每日 IN 柱，缺记录是未知，明确 FASTED 才是没吃。四周台账各自展示有记录且已结束的日均；英雄按对应有效天数加权。

数字不能再串成一行。五位数并排会读成 `1487016580-1710`。周/月英雄用上下三行；表内数字用定宽栏 + Jost + nowrap。Doto 只留英雄。热量差额的英文是 `DIFF`、中文是「差额」——`L("GAP")` 仍是热力图空格的「空窗」，两词不要混。日档消耗线分别按时间累积静息、按有效 MET 分配活动；MET 缺失才用步数估算。两分量与已结算的消耗一致。

`LOG A MEAL` 是食物卡上的琥珀状态，点开是一块从底下推上来的 plate（后面收成圆角卡片、缩到 0.88、压一层半透明黑），chrome 和画像页 `SheetFrame` / 加号抽屉同一套。`MARK TODAY AS FASTED` 仍是现有的服务端事务。`MealEntry` 仍是一餐一行（一份 kcal + P/C/F），ITEM 用 `meal.text`。过去日的翻页只活在 DAY，范围仍是最近 7 个用户日。

算术在 `FuelWindowMath`。2026-09-06 用户要求核对卡路里算法与数据准确性后，重开原来的「缺项当 0、周合计除以 7」规则：缺测不能被解释为零消耗并拉低典型日。IN、OUT 各按自身有效记录统计，无记录的通道显示 `——`；DIFF 只统计同一天同时有 IN 和 OUT 的记录，不跨天配对。展示计入的天数，未结束的今天不进月度典型日。月不把 28 天加总。首页只预载约一天，进这页要自己 `load(days: 27)`，原始点必须分页读完。
