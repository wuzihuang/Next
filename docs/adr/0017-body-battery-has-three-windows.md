# 身体电量也有日 / 周 / 月，主数字永远是一天的 0–100

2026-09-06 用户确认：身体电量按 Paper `13A` / `13B` 方案一（CURVE）落地。一级模块落在「我的」身份卡与 COMPOSITION 之间，整块一热区。二级页同一页 `BODY BATTERY`，顶上是 `SegmentedPills`（DAY / WEEK / MONTH）。主色为产品标准黄 `NB.lime1`。从「我的」进，返回回「我的」；从面板进，返回回首页，只记一层入口。

同日算法审计后的修订以真实时间、完整结算结果和独立证据质量为准，取代早期设计中的个人常态充电词、FULL 预测与手工重锚。具体公式、字段及验证入口见 [PRD 13](../prd/13-body-battery.md)。

三个窗口都按本地 0 点用户日（ADR 0020）：日为 1 天，周为滚动 7 天，月为滚动 30 天，不是自然周月。DAY 的主数字为当前电量；WEEK / MONTH 为有效晨值的平均，均保持一天的 0–100 尺度，不加总。算术在 `BodyBatteryWindowMath`，缺晨值的日期不填零。

晨值绑定实际最终 `wake_at`，不取首个连续睡眠段末值或全天峰值，也没有虚构时刻兜底。当天训练目标从已发布的整数晨值按固定表分档，白天电量变化不使目标滑动。没有历史 close 或可定位睡眠时，有效白天测量可从显式假设 50 开始估计；此时没有晨值或晨间训练目标。假设起点的来源继续保留，不因生成一个次日 close 就消失。

日内归因和整夜充电必须分开：WHY 的 `day_charge + awake + movement + stress = current − anchor`，起点是用户日 0 点或当日醒来时刻中较晚的一个；旧 `last_night` 仅兼容日内充电项。昨夜卡、入口文案和夜间统计只用真实整夜 `night_charge`，缺失时不以日内充电替代。充电词按整夜充入整数点数统一为：

| 点数 | 标签 |
|---|---|
| <20 | LIGHT CHARGE |
| 20–31 | MODERATE CHARGE |
| 32–44 | STRONG CHARGE |
| ≥45 | VERY STRONG CHARGE |

这些是绝对量的展示分档，不能表达“比本人平常如何”或“已充满”。睡眠恢复渐近 95，因此删除到 100 的 FULL 线性预测。证据齐全、连续安静 20 分钟之后的静休项保留原系数和预算，只抵扣一部分清醒消耗、减慢放电，不宣传净充电。

身体电量的数字、曲线、归因、真实观测时间、醒来时间、置信度和版本必须来自一次权威完整结算。即时心率 / 压力不单独覆盖电量主数字。页面同步按钮读取真实数据并等待结算，不能将当前值还原晨值或人为下调目标。

身体电量质量独立于身体成分：使用专属 `LOW / MEDIUM / HIGH` 及夜间 / 白天覆盖率，旧记录缺质量信息时为 LOW。缺测不代表没有压力，也不能据此判定未佩戴。覆盖充分与起始电量准确分别说明；详细基线工程门槛由 PRD 13 记录。

所有当前值入口按自己的观测时间评估：不足 90 分钟正常，满 90 分钟至不足 6 小时变暗并显示实际时间，满 6 小时、缺时间或未来时间显示 `——`。页面每分钟重评，其他指标更新不能延长身体电量有效期。曲线逐段增减着色，超过十分钟的观测间隙断线；末点只表示最后观测。轴和曲线共用真实用户日秒宽度，DST 的 23 / 25 小时仍以本地 0 点为两端。

MONTH 的虚线格表示“无晨值”，不等于“未佩戴”。顶部统计采用互补的“有晨值 / 缺晨值”，不把佩戴日和缺晨值日当成互斥两组。`weekRolls` 从末尾每 7 天切，30 天实际为 `2 + 7 + 7 + 7 + 7` 五组，界面显示每组天数。

身体电量页不展示睡眠分期 / 时长 / 分数。首页约预载一天，详情页按 `DetailWindow` 补齐最多 29 个历史日。DEBUG 入口为 `NB_DEBUG_BODY_BATTERY_RANGE=DAY|WEEK|MONTH`。
