# 运动心率与热量修复验证（2026-09-04）

## 结论与范围

修复了每次运动的指标初始化、暂停/断流期间的热量积分、实时 SDK 热量单位处理和个人资料同步确认。普通、步行、骑行三种模式及重新启动 App 接回运动已通过真机验证。用户描述的固定每次跳 50 尚未复现，不能据此宣称该现象的根因已定位。

## 已确认的问题与处理

- 原积分把最新心率用于整个间隔，并将长间隔截为 15 秒；缺少心率或暂停没有可靠切断积分。新的不可变 `SportMetricAccumulator` 仅在相邻有效读数间积分，超过 15 秒、断连、暂停、缺失读数和时间倒退都不会跨间隔补算。
- 每次新运动重新创建累计器，重置当前、平均和最高心率以及热量。保留设备原始有效心率，不通过平滑或限制变化幅度掩盖真实变化。
- `VPDeviceSportControlModel.calories` 是未标注单位的整数，不能直接当 kcal。保留为 `rawCalories`，只有明确归一化的 `caloriesKcal` 才可作为设备累计热量，且零是有效值。新旧历史 API 的单位不同，不能套用历史换算比例。
- 目前真实设备实时热量采样全部为零，历史接口未返回可配对记录，不能确定单位及可用性。因此实际界面明确显示心率公式的“估算消耗”；重新接入正在进行的运动显示“加入后估算消耗”。资料不足时不使用虚构体重估算。
- SDK 个人信息写入原来忽略返回值，现在仅 ACK=1 判成功。运动开始前同步有效实际资料，发送前和确认后核对当前账号、设备绑定、同意和连接状态。
- 离线和失去接触时先清除当前心率，再更新 Live Activity，避免发送旧读数。

心率估算沿用原有 Keytel 系数，仅修正输入、时间积分和来源表达；没有证明该公式对每一种运动的生理准确性。方法来源：[Keytel 等原始研究](https://pubmed.ncbi.nlm.nih.gov/15966347/)。

## 尚待定位

固定 +50 的具体运动模式、原始数值序列或录屏仍未获得。回归测试明确保留真实的 50→100→150 心率输入，同时验证未知单位原始热量的 +50 不会变成界面的 +50 kcal；不能将这两项测试解释为已复现用户遇到的现象。
