## 真实测试打出来的问题（都已修 + 重新部署）

1. **图表工具的参数是严格类型，模型一写字符串就整轮死**。`screen.render.food` 收到 `{"kcal":"350"}` 或漏掉 `title`，SDK 抛 `AI_InvalidToolArgumentsError`，整轮回落到电量帧。语音报餐和图片报餐两条路都栽在这里。改法遵循 charts.ts 自己写过的教训（enum 也踩过同一个坑）：数字用 `z.coerce.number()`，`title` / `sentence` / `headline` 收成 optional，缺了在 `execute()` 里返回 `MISSING_TEXT` 让模型补一次——**一个缺失的词只能是工具结果，不能是异常**。
2. **图片里读到的数字进不了账本**。`image.inspect` 把「101」放在 `visibleText` 字符串里，账本只收数字叶子，模型引用时被判 UNTRACEABLE。现在字符串里的数字也入账。
3. **计划里模型自己换算和加总**。「432 分钟」写成「7 小时 12 分」、把几餐蛋白相加成 86g，都被审计打掉。计划提示词加了明确的数字规矩：原样照抄 source_data，不加总、不换算、不算差值。
4. **ring 的图表规则要模型说「还差多少」，服务端却不算这个数**。模型只能自己减（21 − 2.6 = 18.4）然后被审计拒绝。按 F7 §08「她想说的差值，服务端必须提前替她算好」，`load.today` 和 `battery.now` 现在返回 `left`。
5. **账本的日期白名单差点误伤区间**。为了让计划里的「9-04」「9/5」过审加的 `\d{1,2}-\d{1,2}` 会吃掉「12.5-16.5」的中间段，留下两个没人写过的数。改成真正的月-日形状并两侧禁贴数字和小数点，`_shared/ledger.test.ts` 锁住。
6. **读注册表里没有睡眠分**。ADR 0008 每晚结算 0–100 的分数、睡眠页也在印，但 `DATA_METRICS` 里没有，Chat 里问「睡眠分和训练负荷有关系吗」，模型如实回答「系统里没有睡眠评分这个指标」然后退而用时长。已加 `sleepScore`（night_score.score，RLS 本来就允许本人读）。

## 第二轮：把上面观察到的也修掉（2026-09-06 傍晚）

覆盖跑完之后按「全部修复」又做了一轮。全仓 Deno 203 个测试通过，iOS Debug build 通过。

7. **任何严格类型的工具参数都是地雷**。`workflow.ready` 收到字符串形式的 range、`data.read` 收到猜出来的指标名 `fatMassKg`、`app.open` 收到不存在的页面——全都是 `AI_InvalidToolArgumentsError`，全都打死整轮。现在**每一个工具参数都是宽松的**，在 `execute()` 里判断：要么规范化后交给手机，要么返回一句模型能照做的话。覆盖 `_shared/phone-tools.ts` 的十个手机工具（新增 `normalizePhoneArgs` 和四个规范化函数 + `phone-tools.test.ts`）、`data.read`、`metric.compare`、`workflow.ready`。
8. **闹钟差点设错星期**。模型把 days 发成 JSON 字符串 `"[1, 2, 3, 4, 5]"`，按逗号切开后 `[1` 和 `5]` 不是数字被丢掉，手环拿到的是周二三四，而屏上写着「周一到周五」。现在先尝试 JSON 解析、再剥掉方括号引号，并且**先认词组再认字**（「工作日」以「日」结尾，逐字读会变成周日）。这是这轮唯一一个会写错真实设备的 bug。
9. **`fatMassKg` 图上有、读不到**。`composition.dual` 画的就是脂肪量，读注册表里却只有体脂率和瘦体重。已补，并加了一条测试断言「图上画的指标必须都能读」。
10. **禁语误伤**。`已记录 0 餐` 被当成写入声明扔掉了——那是在数用户自己的记录。规则改成后面跟数字时放行，`logged` 同理。
11. **Chat 的合规口径**。Chat 按设计不过滤禁语，所以出现了 emoji 和「都在正常范围」。教练提示词现在明确禁止 emoji 和参考区间判定（要比就和这个人自己的基线比），中文的「正常范围 / 参考范围 / 正常值 / 异常 / 偏高 / 偏低」也进了 `banned_phrases`（迁移 `20260906235000`），显示屏那侧照样拦。复测的医疗提问回答干净：只和他自己的基线比，并说明单次 94% 不构成医学判定。
12. **解不出的帧会让首页卡在 THINKING**。服务端学会新类型而 App 还没更新时，`widget(from:)` 返回 nil，首页就永远停在思考态。现在退回成一张文字帧，把 envelope 自带的标题和句子印出来。
13. **12 周体成分问题超时**。读的是 84 天窗口、模型顺序读三四个指标，每一步都要重发整段上下文。改了三处：读工具可以并行、`workflow.ready` 可以和读放同一步、带 source 的图不必再读同一指标；同时把截止时间按 ADR 0005 早就记着的「文档 55 秒 vs 代码 50 秒」对齐到 55 秒。`chart-dual` / `chart-recomp` 从超时变成出帧。
14. **读工具现在报告它覆盖的窗口**。「12 周窗口内仅 2 天有记录」曾被判成不可追溯的 12——时间跨度只对带时间戳的序列可推导，对读取的日期范围反而不行。`data.read` 的 stats 现在带 `days` 和 `weeks`。

## 观察到但没改的

- **每小时 60 轮的上限是真的**：连续跑到第 60 轮开始返回 `RATE_LIMITED` 加 SLOW DOWN 帧，测试台只能等窗口滑开。产品行为正确，但也说明一次密集走查必须分批。
- **Chat 不过滤禁语**（`banned = isChat ? [] : thoughtBanned`，设计如此）。所以 Chat 里出现了 emoji（🚴 ✅）和「都在正常范围」这类参考区间说法；显示屏那一侧不会。要不要把中文的「正常/异常」也纳入禁语、Chat 要不要禁 emoji，是产品决定，我没动。
- **`wave`（心电）永远画不出来**：`PANEL_TYPES` 里有，但没有任何数据源喂它，产品也不呈现波形。
- **图表工具的 schema 太大，是当前最大的延迟来源**。33 个渲染工具序列化后 41k 字符，每一个模型步都要重发（读阶段只发读工具，渲染阶段发全部）。简单图表现在 25–30 秒，接近 55 秒预算；并发三路时偶发超时。我把重复的槽位描述瘦了身（44k → 41k），真正的大头是每个工具都带一份 `claims` 嵌套 schema。要继续降，得动「一图一工具」这个设计——那是 F4 的裁决，不该我一个人改。
- **部署带上了别人未完成的活**：我为了发自己的修复，`supabase functions deploy turn` 用的是共享工作树，里面有另一个 session 正在做的「面板缺口」六种新帧（score / poincare / matrix / call / curve / response，见 `docs/plans/2026-09-06-panel-catalog-and-gaps.md`）。服务端这半边是完整的（类型进了 `PANEL_TYPES`，数据源和技能都在，177 个测试全绿），当时 App 的 `PanelType` 里还没有这六个。**他们随后把客户端补齐了**，我这边另外加了一层兜底：解不出的帧退回文字帧而不是让首页卡住（见上面第 12 条）。
- **ASR 会听错**：合成语音「今天心率怎么样」被转写成「今天新绿怎么样」。模型没有硬猜，回了身体电量帧。真人说话大概率更准，但这条链路的第一环有噪声是事实。
