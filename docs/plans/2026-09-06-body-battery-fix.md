## 修复结果

| 范围 | 修复后的合同 |
|---|---|
| 睡眠时间 | 按真实分期偏移、实际记录区间展开；保留分段空档；同一夜去重，无法定位的汇总不扩充成整段睡眠。 |
| 晨值和跨日 | 绑定真实最终醒来时刻。夜间短暂清醒不会提前冻结。整夜充电单独求和，用户日四项归因仍从当地 04:00 起算。历史子日重放使用该日截止时刻，不能利用未来的夜间证据。 |
| 起点 | 首次有睡眠证据从假设 20 起算；仅有白天证据时从假设 50 起算且无晨值。起点假设随衍生结果保留，不因生成一条中间收盘记录而消失。 |
| 夜间数据 | 实际睡眠分钟内的有效分钟 HRV 优先，五分钟数据按自身覆盖补充；缺失、显式空、无效撤销分别处理。HRV 和 RHR 分别计算覆盖、最长缺口及合格历史夜数。 |
| 个人基线 | 使用最近 14 夜中合格夜；单项至少 5 夜才启用其倍率。基线方差使用明确尺度下限，避免近恒定基线突然失去响应。 |
| 放电 | 保留 HRR/MET/步数取最大项的去重逻辑。临近零时缩放有效归因，使消耗和储量变化闭合。Swift 参考引擎的倍率下限与 SQL 统一为 0.65。 |
| 静休 | 必须有心率、HRV、压力和零步数证据，连续安静完成 20 分钟后才计抵扣。保留原系数，因此只是减慢放电，未将其宣传成净充电。 |
| 接入和缓存 | 凌晨按 SDK 自然日读取正确历史页；保存 MET。RR 保留原序号，不跨缺失值拼接相邻差。晚到的同源读数可修订旧值，旧重试不能回滚较新观测，明确失效的 HRV 不被旧缓存复活。 |
| 夜间计算性能 | 按夜只解析一次 HRV 撤销列表，避免每个粗数据补充分钟重复合并整夜 JSON。`bb-2.1` 的所有输出字段保持不变。 |
| 原始数据写入口 | 客户端仅通过同步 RPC 写原始样本；撤销原始表直接写及已退休补值 RPC 权限，防止绕过来源、时间和撤销规则。读取、服务端归档与账号私有修订审计保留。 |
| 发布和刷新 | 服务端一次发布当前值、曲线、归因、专属输入、时间和版本；客户端不再用单次实时心率覆盖电量。刷新走实际同步，不写回晨值或手工重设目标。 |
| UI | 整夜充电与用户日恢复分开；置信度来自身体电量自身；分别显示 HRV/RHR 合格基线夜数及日夜覆盖率。90 分钟变暗、6 小时隐藏，未来时间不可当作新读数。Widget 使用独立电量时钟。 |
| 曲线和标签 | 按相邻点升降着色、断开缺口；真实时间轴支持 23/25 小时日。移除无法达到的 FULL 预测，统一四个绝对充电量词。30 天完整展示 2+7+7+7+7，缺晨值不标成未佩戴。 |

数据质量门槛目前为至少 60 个有效覆盖分钟、覆盖实际睡眠分钟至少 50%、最长缺口不超过 90 分钟，并要求该夜已经结束。这是明确的工程门槛，不是生理准确度证明。coverage 的 HIGH/MEDIUM/LOW 描述输入充分程度；估计起点的不确定性单独保留。
