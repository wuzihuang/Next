# 身体电量全天充放电与动态训练建议 · 2026-09-15

## 结论与交付

旧模型 `bb-2.2` 的核心问题在规则结构：静休项无法产生净恢复，非运动心率升高被遗漏，睡眠恢复分支缺少当下生理负担，训练目标固定依赖晨值。增加传感器字段或单独调大一个系数不能解决这些问题。

已实现 `bb-3.0` 并按用户确认方式接入另一个同期任务的睡眠 / 恢复基础目标：**最终建议 = min(基础目标, 当前电量限制)**。疲劳时降低，恢复后逐步回升；晨值与已完成负荷保留。交付为本地代码、数据库迁移、场景测试和更新后的产品合同，未部署线上、未重算真实账号。

长期规则集中在 [PRD 13](../prd/13-body-battery.md) 与 [ADR 0017](../adr/0017-body-battery-has-three-windows.md)；本文只记录本轮诊断、实现选择和验收证据。

## 已复现的根因

| 问题 | 旧实现证据 | 本轮处理 |
|---|---|---|
| 静休只能稍慢放电 | 每五分钟抵扣至多 `0.05×(80−BB)/80`，每日预算 5，低于基础消耗；还要求多个传感器同时齐全 | 确认持续静休后独立计入恢复；放宽缺失传感器的支持方式，已有冲突信号仍可阻止充电 |
| 静止时高 HR 漏计 | 没进运动 HRR 区间就没有相应活动价；缺少与个人安静 HR 比较的负担项 | HR 相对同情境常态的升高独立参与生理负担，运动和静止用不同上下文 |
| 压力的影响偏弱 | 旧压力 / HRV 原始率最高约 0.15 / 0.12，持续严重负担仍难降得足够低 | 连续强度建模，较严重负担非线性增加消耗；相关信号只增加有限佐证权重 |
| 睡眠标签覆盖生理状态 | 充电分支主要由分期与整夜倍率控制，不看当槽高 HR / 高压力 / 低 HRV | 当前负担降低恢复质量；严重时睡眠期间也可净放电 |
| 基线情境与时序不匹配 | 白天 HRV 比较夜间 HRV；当晚升高的 RHR 可能成为该日参考值 | 当前日之前的独立历史基线；白天静休与睡眠分开；稀疏记录不启用个人基线 |
| 目标不跟状态走 | 服务端旧目标与客户端兼容表按晨值分档 | 保留睡眠 / 恢复基础目标，连续电量限制叠加其上；下降即时、上升取近期平滑值 |
| 辅助数据未进入模型 | 夜间血氧另表存储；已有皮温不参与；精细运动证据可能缺少粗粒度 origin 对应点 | 按真实时间匹配、持续变化确认；补充真正记录的运动秒数并避免同源重复消耗 |

修改前先添加行为测试再执行，出现六项失败断言。实际旧 Swift 引擎输出：

- 从 50 开始，HR55 / HRV55 / 压力20 / 零步 / MET1 静休两小时，结束为 **47.98**。
- 从 50 开始，六小时浅睡，平稳状态与 HR90 / HRV20 / 压力90 均为 **72.05**，无法区分恢复质量。
- 从 85 开始，HR90 / HRV20 / 压力90 持续十二小时，仍为 **46.46**。
- 零步 / MET1、缺 HRV 与压力时，HR72 和 HR90 两小时结果相同，均约 **47.60**。

这些是实际实现的受控反例，不是某个真人应有电量的推定。

## 实现范围

1. [主迁移](../../supabase/migrations/20260915080239_adaptive_body_battery.sql) 增加纯速率函数、个人同情境基线、全天回放与电量目标限制；保留完整结算、归因闭合、真实时间、历史 profile 和缺测合同。
2. [组合目标迁移](../../supabase/migrations/20260915081432_training_target_follows_current_reserve.sql) 保留同期训练任务的 `training_recovery_target`，只组合当前储量限制，复用其结算缓存。基础目标校准测试直接测基础函数，另用完整结算测试检验两者的最终联动。
3. [Swift 参考模型](../../app/NextBody/Services/Band/BodyBatteryEngine.swift) 与 SQL 的五分钟计算保持相同方向和参数，用于确定性场景测试，不成为手机端权威计算路径。
4. 身体电量页改为说明睡眠和持续静休恢复、生理负担消耗；训练页保留基础目标依据，并显示电量限制、剩余负荷和观测时间。旧缓存中缺少新字段仍可解码，已明确发布的空目标不能回退成旧表的确定目标。
5. AI 增加 `trainingTarget` 指标读取，直接读取发布结果，保留真实 0、未知与账户边界。旧电量限制仍在时标记 stale，避免被解释为实时建议。训练页每分钟独立检查观测时间，页面一直打开也不会将旧值持续标成 CURRENT。
6. 新版本使旧派生结果失效，兼容归档恢复及按日顺序重算；`bb-2.2` 的 close 不直接成为 `bb-3.0` 的起点。新增内部函数保持私有，无新增跨账号查询接口。

以下来自完整迁移链上的合成用户，均有六日历史，前日测试锚点设为 60。白天静休 HRV 基线45、睡眠 HRV 基线65；温度基线分别33°C / 34°C。数值只用于对照工程行为。

另验证：完全无观测不产生新电量；未来样本不能进入当前回放；只有精细运动心率也会计入实际时长的消耗，重复上传不重复扣电；已记录力量训练会阻止低 HR / 零步导致的错误静休充电。

### 训练目标完整联动

同一合成用户按 08:00、14:00、18:00 真实结算流程发布：

| 阶段 | 当前电量 | 睡眠 / 恢复基础目标 | 最终训练建议 |
|---|---:|---:|---:|
| 晨间 | 80 | 15.1 | 14.4 |
| 六小时持续高负担后 | 38 | 15.1 | 7.6 |
| 再经过四小时静休 | 46 | 15.1 | 9.1 |

三个阶段晨值相同、已完成负荷不减。20:00 没有新电量证据时仍保留 9.1，并明确标记旧观测；不会因读数过期回升到 15.1。电量瞬间回升时使用最近十五分钟均值限制目标上升，下降则直接跟随较低的当前值。

## 证据边界与后续标定

白天也存在生理恢复、持续负担可能影响睡眠期间恢复，这一方向与 Firstbeat 的公开方法说明一致；它不提供本项目的速率或阈值标定。[Firstbeat 日间恢复说明](https://www.firstbeat.com/en/blog/i-sleep-enough-so-why-does-daytime-recovery-matter/)

饮酒研究在同一受试者饮酒 / 不饮酒日之间观察到与剂量有关的自主神经恢复变化，支持让实际 HR / HRV 反应参与模型，不能据此推导“每杯酒扣几分”。本模型也不能从这些非特异信号反推用户喝酒。[Pietilä 等，2018 原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC5878366/)

当前设备没有可信平躺标签；低 HR 必须结合活动和可用自主神经证据，不能等同于睡着。皮温不是核心体温，夜间血氧不是白天持续监测。辅助修正必须有连续证据，缺失时不虚构正常读数。这里只验证实现和方向，未宣称模型经过临床验证、真实用户分数准确，或已识别饮食 / 饮酒原因。

后续纵向标定应使用已授权的连续佩戴记录，配合主观精力、记录的静休 / 午睡、训练和生活事件；按整日保留验证集，比较误充电率、高负担后的下降幅度、目标波动及个体差异。阈值调整通过新版本回放同一组场景与历史，不直接改已发布分数。
