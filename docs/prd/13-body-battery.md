# 13 · 身体电量 — BODY BATTERY

来源：设计节点 `1CC9-0`、Paper `13A` / `13B`，见 ADR 0017。
2026-09-15 用户确认：全天按生理状态充放电，并在睡眠 / 恢复给出的基础训练目标上增加当前电量限制。
当前模型为 `bb-3.0`，组合训练目标为 `target-1.1`。本次裁决替代“清醒只能慢放电”和“目标固定取晨值”的旧规则。
实现与审计记录见 [2026-09-15 审计](../plans/2026-09-15-body-battery-audit.md)。

## 页面与时间窗口

- **晨间卡**：每个用户日最多一次，在真实最终 `wake_at` 起六小时内展示。需要晨值、醒来时间及整夜 `night_charge`。晨值是历史读数，不随白天电量变化而改写。
- **DAY**：当前电量、实际观测曲线、WHY 四项归因、恢复依据、心率 / 压力、独立数据质量及同步入口。身体电量页不重复展示睡眠时长、分期或睡眠分；训练建议在训练页。
- **WEEK / MONTH**：滚动 7 / 30 个本地用户日，展示有效晨值的均值，均为一天的 0–100 尺度。缺晨值不填零。30 天分为 `2 + 7 + 7 + 7 + 7` 五组。
- 用户日按本地 **00:00 → 次日 00:00**（ADR 0020）；DST 按真实 23 / 25 小时绘制。整夜充电按实际睡眠区间独立统计。
- 没有夜间记录但有有效白天测量时，可显示带估计起点的电量；没有充分基础目标证据时，训练建议仍为空。

主色为 lime。每个观测上升段用 lime，持平 / 下降段用白色；超过十分钟的观测间隙断线。
末点表示最后观测，不延长到现在；不预测何时睡觉、明早分数或“几点充满”。

整夜充电词只描述绝对充入点数，各入口调用 `BodyBattery.chargeWord`：

| 整夜充入点数 | 英文 | 中文 |
|---|---|---|
| <20 | LIGHT CHARGE | 充得不多 |
| 20–31 | MODERATE CHARGE | 充电适中 |
| 32–44 | STRONG CHARGE | 充得较多 |
| ≥45 | VERY STRONG CHARGE | 充得很多 |

这些是展示分档，不代表个人常态、满电或经过验证的生理阈值。

## 输入与个人基线

| 证据 | 用途 | 缺失与限制 |
|---|---|---|
| 心率 | 活动强度、静止时相对本人常态的升高、接近静息水平的恢复证据 | 不把低于运动区的升高忽略；低心率单独不能证明睡眠或平躺 |
| HRV（RMSSD） | 同情境基线偏离、恢复质量 | 白天静休与睡眠使用不同基线；缺失降低支持程度，不假定为正常值 |
| 压力 | 生理负担与静休证据 | 与 HR / HRV 采用相关信号合并，避免完整重复扣三次 |
| 步数 / MET | 活动量与静止上下文 | 零步不等于静休，骑行和力量训练还要看 MET、心率和已记录运动 |
| 精细运动心率 / 力量证据 | 按真正记录的秒数补足原始五分钟数据 | 会话重传去重，与粗粒度活动取覆盖证据，不能再加一份同源消耗 |
| 可定位的真实睡眠分期 | 恢复区间与分期效率，白天睡眠同样适用 | 不用时钟推断睡眠；不压缩分段之间的清醒空档 |
| 夜间血氧 | 持续偏低时减弱睡眠恢复 | 只与实际睡眠分钟匹配；不把昨夜血氧沿用到白天 |
| 皮肤温度 | 相对同情境个人基线持续升高时减弱恢复 | 这是皮温，不是核心体温；不据此判定发热或疾病 |

基线使用当前日之前的 14 天，排除当前日，防止“今天持续心率高”成为今天自己的正常值。

- 夜间 RHR / HRV 独立筛选有效夜：沿用共享的睡眠分钟覆盖、最长缺口与分钟 HRV 规则；各有至少 5 个合格夜才启用个人基线；本模型另排除范围外的历史 RHR / HRV，不能用脏值建立常态。
- 白天基线只用非睡眠、明确低活动且有有效心率的记录。先取每日中位数，再取跨日中位数，避免记录密度主导基线；每项每日至少 6 个有效五分钟点，至少 5 个合格日。
- 温度区分静休白天和睡眠。夜间温度至少 36 个点且覆盖实际睡眠分钟的 60%；至少 5 个合格夜。偏离尺度为 `max(0.5°C, 3 × 日中位数的 MAD)`，MAD 为绝对偏差的中位数。
- 基线不足时保留缺失与有效天数。用于基础计算的 RHR 55、白天 HR 65 是显式回退估计，不伪装成个人实测基线。
- 目前没有可信的平躺姿态标签，也没有供本模型使用的标准化饮酒剂量 / 饮食反应记录。饮酒或饮食后的影响通过实际 HR、HRV、压力等体现，不凭一条文字记录硬扣固定点数。

## 全天连续充放电

服务端以五分钟格回放，内部保留精度，实际睡眠分钟和运动秒数按比例计入。
概念上：`当前电量 = 上一电量 + 睡眠恢复 + 持续静休恢复 − 基础清醒消耗 − 活动消耗 − 生理负担`。
不以白天 / 夜间时钟开关决定能否充电；0 和 100 是输出边界。

### 生理负担

心率与个人同情境常态比较；HRV 与同情境个人基线比较；压力使用当前有效读数。
各信号归一到 0–1 后，取最强信号加次强信号的 15%，再限制在 0–1，得到 `I`。
当前工程尺度为压力 `(stress−40)/50`、心率 `(HR−参考HR−5)/30`、HRV `(0.9−HRV/基线)/0.5`。

生理负担原始率为 `(0.65 × I² + 0.15 × A × I)`，运动较强时逐步衰减到 20%，以减少运动 HR 与压力的重复归因。
`A` 是持续的温度 / 血氧辅助偏离，范围 0–1；两项取最大支持，不叠加为两份完整惩罚。
持续 HR 升高、HRV 下降或高压力即使发生在零步、低 MET 时也能加快消耗，持续严重负担可以降到很低甚至 0。

### 基础与活动消耗

基础原始率为 `0.15 × 睡眠负债 × (1−0.75×静休质量)`；安静时立即减缓。
睡眠负债沿用 `1 + 0.6 × clamp((420−已记录睡眠分钟)/180, 0, 1)`。
无睡眠记录时，只有用户日头八小时已经结束且至少一半的不同槽有佩戴证据，才按无睡眠负债 1.6；否则为中性 1.0。

活动 HRR 在 0 / .30 / .40 / .55 / .70 / .85 / 1 间连续插值到 0 / .06 / .30 / 1.20 / 3.60 / 6.40 / 6.40。
明确静止时降低活动心率的份额，将非运动 HR 升高交给生理负担。
活动取 HRR、`min(6.4, 0.12×max(MET−1,0))`、`min(6.4, steps/800×0.60)` 的最大项；精细运动证据按真实时长补足，同源证据不重复相加。

总原始消耗为 `D` 时，实际消耗使用储量相关的积分：
`(0.35 + 0.0065×BB) × (1−exp(−0.0065×D))/0.0065`。
低电量时消耗逐渐减小，仍可以到 0；达到 0 时只分摊实际扣掉的部分，保持归因闭合。

### 持续静休恢复

静休质量综合：接近本人静息的心率、明确低活动、可用的低压力 / HRV 恢复证据，以及当下生理负担。
至少需要有效心率和低活动证据；HRV / 压力不全时减弱支持，不要求所有传感器每槽齐全。
任一已有的明显负担证据都会压低静休质量，不能靠“零步”覆盖高压力或训练证据。

连续静休满 20 分钟后开始计入恢复，接下来的 20 分钟逐渐增加速率，不追补确认期。
每五分钟向 90 渐近，工程率为 `0.006 × 静休质量 × 确认后渐增比例`。
它可以超过该段基础消耗、产生净回升；没有每个用户日最多 5 点的固定恢复预算。
缺测、运动或冲突状态中断静休连续性；仅仅没有记录不会充电。

### 睡眠与辅助生理证据

真实睡眠向 95 渐近，工程率为 `0.011 × 分期权重 × 夜间倍率 × 当前恢复质量`。
分期权重 deep 1.25 / light 0.85 / REM 1 / insomnia 0.15；awake 转入清醒。
夜间 HRV / RHR 的独立历史因子组成倍率并限制在 0.65–1.30；基线不足的因子中性。
当前恢复质量为 `(1−I)² × (1−0.6×A)`；睡眠期间仍计入 75% 的当下生理负担消耗。
因此睡眠不是无条件充电：同样睡六小时，恢复平稳与持续高负担可以得到明显不同结果。

温度 / 血氧修正要求至少三个相邻五分钟槽连续支持，缺测中断确认，温度还要求同一睡醒情境。
血氧工程偏离为 `clamp((95−SpO2)/5, 0, 1)`；温度先减去个人基线与偏离尺度，再在 1°C 内渐增。
单次尖峰不改变充放电，温度本身不能凭空制造一份活动消耗；这些工程参数不用于医疗判断。

## 储量、整夜与归因

- `anchor` 为本地用户日开始的储量，衔接前一日同算法未舍入 close。无兼容历史、但有可定位首睡时显式假设 20；只有有效白天测量时显式假设 50。没有证据不发布假定分数。
- `day_charge` 包含本用户日午夜起的睡眠与静休恢复。`day_charge + awake + movement + stress = current − anchor`；`last_night` 仅保留为这个日内项的兼容别名。
- `night_charge` 只统计实际整夜 `sleep_start → 最终 wake_at` 的恢复量，可跨午夜且排除下一晚；晨间卡和夜间统计只读它。
- `wake_value` 为实际最终醒来时的储量，不取全天峰值；白天升降不改写这个历史读数。
- 假设起点的来源随派生储量保留，不能生成一个 close 就声称初始不确定性消失。
- 发布整数时分配舍入残差，WHY 四项必须与首尾值闭合。

## 睡眠 / 恢复基础目标 + 当前电量限制

采用用户确认的整合方式，服务端在同次结算发布全部输入：

1. `nb.training_recovery_target` 保留睡眠、恢复、既有晨值和合格近期训练历史给出的基础目标 `T₀`。
2. `nb.reserve_training_target` 使用 `min(当前电量, 最近15分钟已观测电量均值)` 生成连续电量限制 `C`。
3. 最终建议为 `min(T₀, C)`。下降立即生效，电量恢复后逐渐回升，不能高于当前基础目标。
4. 已完成负荷是独立累计事实，不被目标变化修改；还可增加的负荷为 `max(0, 最终建议−已完成负荷)`，不要求继续凑数。

电量限制在以下节点之间线性插值，没有旧晨值分档的阶跃：

| 电量 | 0 | 20 | 30 | 40 | 50 | 60 | 70 | 80 | 90 | 100 |
|---|---|---|---|---|---|---|---|---|---|---|
| 目标限制 | 0 | 4 | 6 | 8 | 10 | 11.5 | 13 | 14.5 | 16 | 18 |

`daily_training.evidence.target` 是训练页与 AI 的权威建议，包含 `base_target`、`current_reserve`、`reserve_limit`、`reserve_adjustment`、`remaining`、`observed_at`、`reserve_fresh`。
缺基础目标则最终建议为空；旧客户端缓存完全没有目标字段时才允许兼容旧分档，明确发布的空值不能被手机覆盖。
读数超过 90 分钟后保留已观测的限制并标记过期，不能因缺测解除疲劳限制、退回更高的基础目标。
UI 展示基础目标、身体电量读数、剩余负荷与实际观测时间；旧读数不称为当前实时电量，AI 读取也标记 stale。

## 数据质量、新鲜度与发布

当前值、曲线、归因、观测时间、醒来时间、置信度和版本来自一次服务端权威结算，整体替换。
手机只同步、上传、请求结算、读回；`BodyBatteryEngine` 只用于确定性参考和场景测试。
实时心率 / 压力不能单独改写主数字；同步按钮不还原晨值、不重设目标。

新鲜度使用 `observed_at`（实际有证据的最后计算格，最多五分钟粒度）；旧缓存才回退曲线末点。
网络拉取、设备同步和其他指标更新时间不能把旧电量变新。

| 距观测时间 | 当前数字 / 曲线 |
|---|---|
| <90 分钟 | 正常显示 |
| ≥90 分钟且 <6 小时 | 变暗并显示原观测时间 |
| ≥6 小时、缺时间或未来时间 | 当前数字为 `——`；已知历史曲线可保留并变暗 |

页面每分钟重评。缺少近期有效数据不是一个真实的 0，也不能单凭缺测推断静休、未佩戴或整晚没睡。
身体电量质量使用独立 `LOW / MEDIUM / HIGH`，不读身体成分置信度；旧缓存缺字段默认为 LOW。
覆盖包含夜间 HRV / RHR 分钟与缺口、独立有效历史夜数及白天 HR / HRV / 压力覆盖。
HIGH 还要求已启用个人白天 HR / HRV 基线和充分白天覆盖；MEDIUM 要求真实晨值及足够白天心率覆盖。
质量等级衡量数据充分程度，不是统计置信区间，也不证明估计起点或生理准确度。

- 通过新增迁移安装 `bb-3.0` / `target-1.1`；旧结果失效后走现有归档恢复与顺序重算，旧版 close 不成为新版锚点。

所有速率、阈值、目标节点都是可测试的工程参数。场景回放验证方向、确定性和数据合同；尚需设备实测及纵向主观状态对照验证生理准确度，不能把文献或合成场景当作本模型的临床标定。
