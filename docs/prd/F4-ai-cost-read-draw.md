# F4 续 · 成本可核算、读数一张表、先读再画

> 2026-09-05 从产品对话收束，写成 ADR 0005 / 0006 / 0007，再拆成可执行 spec：
> [GitHub #14](https://github.com/wuzihuang/Next/issues/14) ·
> [#15](https://github.com/wuzihuang/Next/issues/15) ·
> [#16](https://github.com/wuzihuang/Next/issues/16)。
> 本篇是三份需求的合订，给产品与实现对照用。屏级规格仍在 F4 原板。

**主张：** 让用户免费用三年这件事要站得住，模型必须看得见库里已有的健康数据，而且必须先读完再画——这三件事是同一条路上的三个闸，不是三个功能。

---

## 从哪来

当时要定的不是「再加几个工具」，而是三件已经互相卡住的事：

1. **不知道一轮花了多少钱。** 服务端从未读取模型返回的 token 用量。对话有日限常量但没执行；估餐和语音转写完全没有限流。绕开对话入口就能无限刷。「一年 ¥43.6、免费用三年」当时全是按假设推的，不是测量。
2. **库里有的，模型读不到。** 皮肤体温、距离、逐 tick HRV、手环原始耗卡、活动分钟、日距离都已经在库里。用户问「我的体温怎么样」得不到答案。新数据要进模型，得在两套平行数据层里挑一套重写一遍已经解决过的问题。
3. **「先读再画」只靠自觉。** 读工具和画工具同时递给模型。它可以读一个维度就开始画，也可以画完再去读——后者已经影响不了那一帧。多步调用每一步重发全上下文，最坏成本没有上界。

同时定下的产品方向：

- 文本、视觉、对话走**同一个主模型**；ASR 保持独立（文本模型不吃音频）。
- 保留 fallback，但**不许降级到更容易编数字的小模型**，也不许落到会拿输入去训练的厂商直供。
- **工具不要做太多。** 以后尽量工具本身不变，只加新表或新字段。数据库里有的健康数据都应该能读出来，不限于界面展示过的。
- 让模型自己按问题决定读哪些数据，读完再选图填图。阶段边界要从提示词里的一句话，变成机械约束。
- 仍然是**一次模型对话、不加传输层**（F4 已裁：第一版不起 MCP server）。

依赖顺序：#16 等 #15 把工具集定型；#14 可以并行。睡眠呼吸率从本批摘走——当时另有一条在飞的手环数据工作，等它落地再决定 AI 读夜间表的原始 jsonb 还是读它可能新建的表。

## 一 · 账：每一次调用都可计数，三个入口同一本额度

依据 ADR 0007。可执行 spec 是 #14。

### 要什么

先把账建起来，再谈花钱的规矩。

每一次模型调用返回的 token 用量都落库，按健康账号、按用户日聚合成可查的视图，三类分开记：输入、输出、缓存命中输入。缓存命中输入的单价是标准输入价的 12.5%，混在一起记就算不出真实金额。多步工具调用的一轮里有多次模型调用，**每次都要记**，并能按轮聚合。

有了这张视图，「每天 10 轮、当天未用可累积到 20 轮」才第一次成为可执行的规则。金额上限与次数上限并存，谁先到谁先拦。

### 额度对用户怎么表现

- 三个入口共用同一本：**对话、估餐、语音转写**。不是三本账。
- 超额是**拒绝，不是降级**：不跑模型。面板保留上一帧（面板永远不许空），再补一帧说明「今天的额度用完了、明天恢复」。
- 用量对用户**只以次数表述，不显示金额**。金额会暴露单轮成本差异，引出不想解释的追问。
- 昨天没问的次数今天还能用，刚戴上手环那几天可以连着问；累积上限是 20，不会攒出一个自己都用不完的数字。
- 现有的突发限流（60 秒窗口）与小时限流保留。它们兼职防刷与防并发，不能被日限替代。小时超限走电量降级帧是错的语义，要改成说明帧。

累积是纯算术，不需要每天跑定时任务：可用余额 = min(20, 上次结算余额 + 距今天数 × 10)。计数放 Postgres，端点无状态。

### 模型

- 主模型只有一个：`qwen3.8-flash` 承担文本、视觉与对话。标识可配置，切换不改代码。
- **删掉独立视觉模型之前，必须先用一张真实照片打通主模型的图片输入**，并把返回的用量记进 `docs/STATUS.md`。仓库里曾有「该模型没有图片输入」的实测结论，只能用另一次实测推翻，不能凭文档。这次实调是把所有估算换成实测的第一个数据点。
- ASR 模型保持独立。实时语音通道保留：它买到的不是字幕（中间结果在客户端被丢弃），而是说话时就在上传带来的松手后延迟。
- fallback 只收阿里云百炼**直供**（模型标识不带厂商前缀）。候选：`kimi-k3`（可读图，¥20/¥100）、`deepseek-v4-flash`（纯文本，¥1/¥2）。带前缀的原厂直供出链——请求实际落到厂商侧，训练权利重新生效。`qwen3.8-flash-next` 也不在百炼上，出链。
- fallback 只在模型不可用时触发。额度用完与模型挂了是两套互不调用的机制。
- 准入三项齐全：工具调用、结构化输出、流式思维链字段。严格 JSON Schema 只有主模型系列支持；估餐与照片读数在 fallback 时允许退化成「提示词要求 JSON + 自己校验重试」。
- 原「主模型 3 秒无 token 就切小模型」作废：从未实现，且会降级到不可信。

### 为什么要金额上限

按真实单价重算之后，PRD 里「一轮一次调用、月成本 ≤ $0.9」这条破了。多步工具调用每步重发全上下文；一句「现在心率」和一个「看这张照片并对比过去 90 天」差几十倍。次数限流拦不住单轮方差，所以次数与金额谁先到谁先拦。

隐式缓存自动开启且无法关闭。要吃到它，系统提示词与工具定义必须**逐字节稳定**（见第二节删关键词预路由）。显式缓存不用：创建价比标准输入贵，五分钟 TTL，移动端偶发触发回不了本。

### 本块不做

- 本 spec 只做成本约束。变现落在 ADR 0030（NextBody PRO）。没有 Pro 不跑模型；有 Pro 仍受本块额度约束。
- 向用户展示金额。
- 成本看板的前端。本 spec 只到「数据可查」。
- 自建推理服务。

## 二 · 读：一张声明式注册表，加数据只加条目

依据 ADR 0006。可执行 spec 是 #15。

### 要什么

把四个读数工具合成一个 `data.read`，背后共用一张声明式注册表。以后加数据只加条目：声明它在哪张表哪一列、什么单位、什么粒度、是实测还是派生，分页、按用户日对齐、缺测算破折号、统计量与整套证据元数据全部自动继承。

另给一个 `data.catalog`：模型自己问「有哪些数据可读、什么单位、什么粒度、这个人有数据的区间是哪段」，而不是靠正则替它猜。

### 注册表要补的三样

1. **粒度。** 按天、按次测量、按 tick。tick 类支持分桶，服务器按返回点数封顶——否则五分钟一行的列根本表达不了。
2. **证据语义写在条目上。** 实测还是派生、测量时间取哪一列、要不要检查过期。不要再按表名 if。加一张新表不必回来改那几行。
3. **日汇总表的查询列从注册表收集。** 往里加个字段不必改硬编码列串。

### 白名单的界

界线画在「测量与派生的健康数据」对「系统自己的账」，**不是**画在「界面上有没有」。

- 进：健康测量与派生，包括界面从未展示过的列。
- 不进：AI 轮次表、屏帧表、限流计数、个人档案。让模型读得到自己上一轮写在屏幕上的数字，数字账本的审计就失去意义——它能把自己编过的数字再读回来当证据。

指标名保持在参数枚举里内联（短名进缓存前缀）。单位、粒度与可用区间由目录提供。

### 时间窗

模型提区间，服务器按用户日（04:00 切日）对齐并封顶。超限**截断并标明被截断**，不是假装给了完整历史。这不是不信任模型判断该问哪一段，是不让它决定能从库里拖走多少行。

同理拒绝「每轮把所有维度都读一遍」：账本容量与单轮时间预算都装不下，屏上数字也更容易因为碰巧对得上而通过审计。

### 删关键词预路由

正则只认中英词。用法语问、换个说法问、接着上一句问，都会失效。它与「让模型自己选数据」相反。

真正的代价不在准确率：命中时它会裁短系统提示词里选图那一节，提示词逐字节改变，隐式前缀缓存在命中与未命中的轮之间互不复用——大约 45% 的输入成本，用来换省下的一圈读取。删掉它，系统提示词必须与提问内容无关。

### 第一批六个维度

前四个在原始采样表，列已在库里、上传已通；同批加两个日汇总。

| 维度 | 粒度 | 单位 | 默认分桶 | 聚合 | 来源 |
|---|---|---|---|---|---|
| 皮肤体温 | tick | °C | 30 分钟 | 均值 | 实测 |
| 逐 tick HRV | tick | ms | 30 分钟 | 均值 | 实测 |
| 手环原始耗卡 | tick | kcal | 2 小时 | 求和 | 实测 |
| 距离 | tick | m | 2 小时 | 求和 | 实测 |
| 活动分钟 | 按天 | min | — | — | 派生 |
| 日距离 | 按天 | m | — | — | 派生 |

分桶按数字账本容量定，不按视觉效果定。原始采样一天约 288 点；30 分钟得 48 点、2 小时得 12 点。累加类用求和，因为 tick 存的是区间增量。

**手环原始耗卡必须单独约束。** 它不是本产品的消耗口径。展示用的消耗走当日燃料表，由服务端从 MET 与体重算出（ADR 0004：厂商卡路里不与计算基础代谢相加）。条目说明必须写明这是手环自报的原始值，且不要给它配一个叫「消耗」的标题。缺测写破折号，不写 0。活动分钟不得与训练负荷混为一谈。

夜间血氧当时标成不支持，但夜间血氧图已经能从氧气采样表读到。补条目时对齐：它是**记录到的睡眠窗口内的自动读数**，不是日间手动测量。

### 不并入注册表的

- 约十九个图表数据源做了通用注册表表达不了的整形（热力、泳道、双轨、堆叠、睡眠窗定界的血氧图、多表事件排序等），留在绘图层。
- 指标相关性：算的是相关系数，是分析不是读数。
- 当日汇总：返回的方向与结论是服务端算好的产品判断，不该让模型自己拿零件组装。

绘图工具填点时仍然自己查库，不消费 `data.read` 的点列。原因见第三节。

### 本块不做

- 睡眠呼吸率（等并行的手环数据工作落地）。
- 食物反应点作为模型可读维度。措辞比接入更重：只能叫 RESPONSE，不许出现血糖、mmol/L、mg/dL 或 SPIKE。单独一批。
- 运动会话单次记录。服务端没有这张表，也没有上传路径；今日分段是从心率抬高段反推的，不是手环运动模式下的一次会话。
- 十九个绘图层数据源的重写。
- 相关性计算与当日汇总的并入。

## 三 · 画：一轮仍是一次对话，取证与制图机械分段

依据 ADR 0005。可执行 spec 是 #16。依赖 #15 先把工具集定型。

### 要什么

把阶段边界从提示词里的 `READ FIRST` 变成机械约束，但仍然只是一次流式调用。

每一步开始前决定这一步能看见哪些工具：

- 第一段只挂读数工具。
- 第二段只挂绘图工具。
- 第二段发现证据不够时，允许回到第一段**补读一次**，仅此一次。
- 步数上限 **6**（第一段四步、第二段两步）。不是放宽。

选择在一次调用内分段，而不是发两次请求：第一版不加传输层；两次请求要多付一次鉴权、冷启动和失败窗口。选择分段而不是两次独立模型调用：同一段对话里换工具集，不必重发上下文。

### 为什么步数要收紧

多步工具调用每一步都重发整个上下文，累计输入对步数超线性。按固定前缀 3k、每个工具返回 800 token 估，八步的累计输入约为一步的 18 倍。给模型更多次机会不是可靠性手段，降级帧才是。最坏情况成本必须有上界，月度成本才能估。

### 绘图仍然自己查库填点

不改成消费第一段的读取结果。数字账本超限时会把返回体的点数组二分砍半直到装得下；一条 288 点曲线的去重值远超账本容量，强制第二段只能用第一段读到的数，曲线就是残的。

审计并不因此变松：账本管的是模型写在句子里的数字，图上的点本来就不在审计范围内。两段之间不冻结账本——在「绘图自取数」这套机制下，「封盘」没有意义。

### 保留不动

时间预算与其后的降级帧、快速失败重试、画成功即中止、幂等轮次标识、思考过程的流式输出、既有的鉴权与预算检查次序。分段不该让第一帧变慢。超时时看到的是明确的降级帧，不是空面板，也不是半张图。

落地时，端点注释、F4 原板与实现必须说**同一个秒数**（当时文档写 55 秒、实现是 50 秒，另有 90 秒数据库租约与之独立）。本需求不裁决改哪一边，只要求三处对齐。

### 本块不做

- 把绘图工具改成消费第一段的读取结果。
- 两段之间冻结账本。
- 提示词里那句自觉约束的删除（结构保证生效后它变冗余，属提示词瘦身，不在本块验收）。
- 时间预算数值本身的调整（只要求对齐）。

## 对用户来说，这些故事必须成立

作为健康账号的持有者：

1. 今天问完第 10 轮之后被明确告知额度用完了、明天恢复，不会以为产品坏了。
2. 昨天没问的次数今天还能用；累积有上限 20。
3. 额度用完时面板上原来那一帧还在。
4. 额度只用次数表述。语音转写和拍照估餐也算在同一本里。
5. 拍照估餐和文字提问得到同等能力，不因为走了不同模型而突然不会用工具。
6. 主模型挂掉时换上来的是同档模型，屏幕上的数字仍然可信；输入不被用于训练。
7. 问皮肤体温、距离、夜间 HRV 的变化、活动分钟，能得到答案；活动分钟不被说成训练负荷。
8. 用法语或任何惯用说法提问、接着上一句追问，能读到的数据和用中文问一样多。
9. 模型引用手环原始耗卡时，说的是手环自报值，不是本产品的消耗。
10. 某一天没测到，屏幕上是破折号而不是 0。问很长的区间时，要么给全部，要么标明只看了一段。
11. 模型不能读到它自己上一轮写在屏幕上的数字。
12. 画图之前已经把该看的数据看完；发现不够能补读一次，但不会因此转很久直到超时。
13. 超时时看到降级帧，不是空面板；曲线上的点不因为换了执行结构而残缺；句子里的每个数字仍然来自真实读数。

作为产品负责人：

14. 能查到任意一天任意一个健康账号的 token 用量与折算金额，「免费三年」有据可查。
15. 能看到输入里有多少比例命中了缓存，以及单轮成本的分布而不只是均值。
16. 额度既有次数上限也有金额上限。
17. 新接一个手环维度时不需要改 AI 的代码，只加一行配置。
18. 模型每轮的系统提示词逐字节稳定，前缀缓存真的生效。
19. 「读完再画」是结构保证，不随模型版本漂移；一轮最坏成本有上界。

作为开发者：这些都必须能在不打真实模型、不打网络的前提下测到——额度放行或拒绝、拒绝时不调用模型、用量有没有被记下来、第一步只看见读工具、补读最多一次、第 6 步后出的是降级帧而不是半张图。

## 怎么测才算测到需求

好的测试只断言外部可观察的行为，不断言内部怎么算的。

| 要钉住的 | 怎么钉 |
|---|---|
| 额度算术 | 给定上次结算余额与经过天数，断言可用余额。边界：刚好 10、刚好 20、超过 20 天不用仍是 20、同一天内连续消耗。 |
| 三个端点的拒绝 | 额度满时不调用模型。这是「拒绝不是降级」的机械证据。 |
| 用量落库 | 假模型返回固定用量；三类 token 都被记下；多步的每一步都记。 |
| 金额折算 | 同样的 token 数在不同单价下折出不同金额；缓存命中按 12.5%。 |
| 注册表行为 | 内存表。每个新条目至少三个问题：问它本身、问缺测日（null 不是 0）、问超出封顶的区间（截断标记）。 |
| 分桶 | 一天 288 行 → 30 分钟 48 点、2 小时 12 点；求和与均值各算对各的。 |
| 白名单 | 健康表能读；轮次表与屏帧表读不到。 |
| 提示词稳定 | 不同用户提问生成的系统提示词完全相同。这是前缀缓存唯一可自动化的证据。 |
| 两段式 | 脚本化假模型记录每步被递到的工具集：第一段只有读、绘图阶段只有画、补读一次被允许、第二次被拒绝、6 步不落帧出降级帧。 |

**不测真实模型调用。** 照片实调是一次手动验证，产出是写进 STATUS 的用量数字，不进自动化测试。

注册表合并后，同一句问法在合并前后各跑一次、比对累计输入 token——这是手动复核，依赖用量采集先落地。确认合并没有把工具描述撑大到抵消掉缓存收益。

## 上线前仍悬着、不得用文档代替结论的

- **真实照片打主模型。** 代码可以把视觉路径指到同一个模型标识；在记下那次调用的 `usage` 之前，不得把图片 token 与单轮成本当成已校准。
- 三处官方文档自相矛盾，上线前要在控制台或用一次实际调用确认：免费额度适用地域、主模型是否支持批量推理（对本产品本来不适用）、隐式缓存最小前缀（按 1024 规划）。
- ASR 类模型要在百炼控制台逐一开通权限才能调用并消耗免费额度。
- API Key 按地域绑定；跨地域调用返回 401 而不是 key 失效。
- 预取的数据源上下文与新鲜度上下文若拼进系统消息，会破坏前缀缓存。落地时必须确认它们只进 user message。
